<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser preview → localhost restore POST | User-controlled archive/slot/fingerprint data requests a destructive target write. |
| Laptop archive → pinned project Buffer | Library bytes may change after shelf rendering or attempt traversal/tampering. |
| Mounted/fixture project → automatic recovery archive | Existing target bytes must be preserved and verified before replacement. |
| Temporary sibling → canonical project | Removable-volume replacement/readback can fail after mutation begins. |

## STRIDE Threat Register — OWASP ASVS L1

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing / Tampering | restore target fingerprint | high | mitigate | Positive request validation plus one guarded fresh capture compares an HMAC-bound opaque source token, slot, SHA-256, and length before backup or write; same-label/same-byte source-replacement tests block the plan. |
| T-03-02 | Tampering | archive bundle bytes | high | mitigate | Canonical containment and current evidence reread/hash/length/parse pin the exact Buffer; a reviewed revision digest must match fresh manifest/project evidence, and corrupt plus different-valid-archive substitution tests verify zero backup/write. |
| T-03-03 | Tampering | current target protection | high | mitigate | Publish and reclassify a verified automatic backup of the captured target before replacement; injected backup failure proves the target remains unchanged. |
| T-03-04 | Spoofing | mounted source versus fallback | high | mitigate | Resolve once under the global guard, retain canonical root/dev/inode identity, and prohibit every later `getSource()`/dynamic path call; substitution tests assert fallback bytes remain untouched. |
| T-03-05 | Tampering / Repudiation | canonical project write and rollback | high | mitigate | Same-directory temporary write, flush, rename, exact reread/hash/length/parse, recovery ID, and equally strict rollback proof; all post-mutation exceptions stay non-success. |
| T-03-06 | Information Disclosure | public receipt/error/UI | high | mitigate | Serialize only stable public codes, sanitized source facts, recovery ID/auto/state, and fixed guidance; tests reject roots, inode/device facts, temp names, stacks, raw errors, and settings values. |
| T-03-07 | Denial of Service | global mutation boundary | medium | mitigate | Preserve reject-not-queue `withMutation()` semantics and `finally` release; concurrency tests prove rejected calls do zero resolver/capture work. |
| T-03-08 | Elevation of Privilege | clear/download routes | high | mitigate | Keep `/api/clear-slot` and `/api/op1fun/download` fenced in the central inventory; full route tests remain blocking. |
| T-03-SC | Tampering | package supply chain | low | accept | No package-manager install, dependency, registry component, or build step exists in this plan; Node/browser built-ins and existing modules only. |
</threat_model>
